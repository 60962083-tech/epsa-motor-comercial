# HU-012 / EMT-72: consulta pública de modelos

## Despliegue

Aplicar `supabase/migrations/202610070002_hu012_modelos_publicados.sql` sobre el esquema compartido antes de desplegar el backend. No requiere HU-002 ni HU-007. Configurar `SUPABASE_URL` y `SUPABASE_ANON_KEY` (clave pública anónima, nunca service_role).

La migración crea una RPC de lectura sin parámetros, ejecutable por anon y authenticated. Su filtro fijo es `modelo.estmod = 'Publicado'`. Usa SECURITY DEFINER con search_path vacío, nombres de tabla calificados y proyección explícita. No concede acceso a las tablas, ni modifica sus políticas, sus registros o las funciones de otras historias. Permisos de lectura directa que ya existan en un Supabase remoto deben revisarse por separado; esta migración no revoca permisos ajenos a EMT-72.

## Contrato público

`GET /api/modelos`, sin Bearer token. Los encabezados de autenticación del visitante no se envían a Supabase. No admite parámetros de consulta; cualquier parámetro (incluidos estado, estmod, select u or) responde 400. No hay endpoints de escritura ni de administración en esta subtarea.

Respuesta 200: `{ "ok": true, "data": [...] }`. Cada ficha contiene exclusivamente:

- `codmod`: ID BIGINT como string.
- `nommod`, `marmod`, `desmod`, `carmod`: nombre, marca, descripción y características existentes.
- `imagenes`: objetos `{ "urlimo": "...", "ordimo": 1 }`, solo imágenes con `estimo = true`, ordenadas por ordimo y codimo. Sin imágenes activas, devuelve `[]`.

Las fichas se ordenan por nombre y código. Sin modelos publicados devuelve una lista vacía. Los errores internos responden 500 sin detalles de BD. Las respuestas llevan `Cache-Control: no-store` para evitar conservar fichas despublicadas en caché HTTP. El frontend deberá consultar nuevamente para actualizar una pantalla ya abierta.

## Alcance y límites del esquema

Para ocultar un modelo basta con cambiar su estmod a `No publicado` mediante el flujo administrativo correspondiente; la siguiente consulta lo excluye sin borrar modelo, imágenes ni referencias históricas. EMT-72 no implementa ese flujo administrativo.

El esquema dispone de nombre, marca, descripción, características, estado y URLs de imágenes. No registra aprobación de fotos o confirmación de datos; `estimo` significa activa, no una evidencia de autorización. Tampoco representa precios por techo/configuración. La API no inventa aprobaciones, precios universales ni almacenamiento de archivos. Las validaciones de publicación/ficha completa y el panel pertenecen a las otras subtareas de HU-012.

## Verificación

Revisión del 7 de octubre de 2026: el esquema local no concede SELECT de tabla ni columna a anon en modelo/imagenmodelo; los tests comprueban los permisos efectivos y que la lectura directa falla, incluso solicitando columnas concretas o estados internos. No se cambiaron grants ni RLS. Todos los modelos publicados del fixture tienen al menos una imagen activa; esto no implementa la validación administrativa de publicación ni acredita autorización de las fotos.

Auditoría de Supabase ejecutada y reportada por el usuario el 7 de octubre de 2026: ambas tablas tienen RLS habilitado, FORCE RLS deshabilitado y ninguna policy; anon tiene SELECT de tabla/columnas. Por tanto, RLS aplica default-deny a la lectura directa de anon y explica las listas vacías observadas por REST. La RPC es SECURITY DEFINER y anon/authenticated tienen EXECUTE. No es necesario modificar grants ni RLS. Se conserva `docs/HU-012-auditoria-permisos.sql` como consulta de solo lectura para futuras verificaciones.

Un test adicional reproduce esa configuración en PostgreSQL local, con datos publicados e internos presentes: anon obtiene listas vacías de ambas tablas y la RPC sigue exponiendo únicamente los modelos publicados e imágenes activas. Los grants y RLS del test se aplican exclusivamente a la BD efímera; no se modificaron migraciones ni Supabase remoto.

`npm test` incluye pruebas HTTP y PostgreSQL local (PGlite) con HU-026 y HU-034: publicación, estados internos ocultos, filtros rechazados, consulta anónima, proyección de campos, imágenes activas, errores y despublicación conservando referencias. `npm run build` verifica TypeScript. Esta rama no contiene la implementación ni los tests de HU-007; no se modifica la autenticación existente. Las pruebas locales no sustituyen la validación del esquema/permisos del Supabase remoto ni aplican la migración allí.
