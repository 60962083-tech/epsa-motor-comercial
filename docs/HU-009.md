# HU-009 / EMT-84: consultar ficha pública de modelo

## Endpoint

`GET /api/modelos/:id` es público y no requiere Bearer token. Reutiliza el cliente Supabase público (anon key) de HU-012. El ID debe ser una cadena BIGINT positiva. Cero, negativos, decimales, texto y valores mayores al BIGINT máximo responden 400:

```json
{ "ok": true, "data": {
  "codmod": "1",
  "nommod": "Modelo prueba 1",
  "marmod": "Bajaj",
  "desmod": "Modelo registrado para pruebas",
  "carmod": "Configuración estándar",
  "imagenes": [{ "urlimo": "https://ejemplo.test/modelo.jpg", "ordimo": 1 }]
} }
```

Los BIGINT se devuelven como texto. La proyección tiene únicamente `codmod`, `nommod`, `marmod`, `desmod`, `carmod` e imágenes activas `{urlimo, ordimo}`. Las imágenes se ordenan por `ordimo` y luego por `codimo`; sin imágenes activas se devuelve `[]`. La consulta fija `estmod = 'Publicado'` en PostgreSQL. No acepta query params. El endpoint responde con `Cache-Control: no-store`.

Un ID inexistente, Borrador, No publicado o despublicado responde idénticamente:

```json
{ "ok": false, "message": "Modelo no disponible" }
```

ID/consulta inválidos responden 400. Un error interno de Supabase responde 500 genérico, sin SQL ni detalles internos.

## PostgreSQL y despliegue

Aplicar `supabase/migrations/202610080002_hu009_ficha_modelo.sql` después de las migraciones existentes hasta HU-004. Crea `hu009_modelo_publicado_por_id(p_codmod bigint)`, sin parámetro de estado ni filtros. Es `SECURITY DEFINER` con `search_path` vacío y proyección explícita; revoca ejecución de PUBLIC y concede EXECUTE únicamente a `anon` y `authenticated`. No agrega permisos de lectura directa ni cambia RLS, políticas o grants de tablas. La función solo consulta `modelo` e `imagenmodelo`.

HU-009 es ficha de modelo comercial, no inventario. No consulta `unidad` ni expone motor, chasis, stock, ubicación, disponibilidad, preparación, compra, cliente, separación o venta. No agrega ni devuelve precios y no afirma entrega inmediata, existencia de unidades o accesorios incluidos. WhatsApp corresponde a HU-013.

El esquema no contiene coloraciones comerciales aprobadas por modelo. `unidad.coluni` describe una unidad concreta y no se usa aquí. Las coloraciones quedan pendientes de una fuente de datos aprobada; no se inventan colores ni se crea un catálogo en esta historia.

## Compatibilidad

`GET /api/modelos` de HU-012 permanece intacto: sigue listando todos los modelos publicados con el mismo contrato y rechaza filtros de consulta. La ficha y el catálogo usan RPC separadas, ambas con la misma proyección pública.

`npm test` cubre HTTP, estados, publicación/despublicación, imágenes y permisos en PostgreSQL local con PGlite. `npm run build` compila TypeScript. Las pruebas locales no aplican la migración a Supabase remoto.
