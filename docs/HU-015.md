# HU-015 / EMT-20 (subtarea EMT-108) — Asignar o transferir un interesado

`lead.codusu` guarda al responsable actual. `lead.codcrelea` conserva al creador del registro y `seguimientolead.codusu` identifica al autor de cada actividad; son conceptos distintos. La asignación se conserva además como un evento independiente en `public.asignacionlead`, sin modificar ni crear seguimientos.

## Endpoints autenticados

- `GET /api/leads`: Gerente y Administradora reciben leads de gestión; Vendedor recibe únicamente los leads cuyo `codusu` coincide con su identidad activa. Acepta `limite` (1–100, predeterminado 50) y `offset` (predeterminado 0). No acepta filtros de usuario ni de rol.
- `GET /api/leads/responsables`: solo Gerente y Administradora; devuelve usuarios activos con rol activo Gerente, Administradora o Vendedor.
- `PATCH /api/leads/:codlea/responsable`: solo Gerente y Administradora. El cuerpo lleva `codusuNuevo`, `codusuEsperado` (incluido explícitamente; `null` para asignación inicial) y `motivo` opcional. Transferir desde un responsable existente requiere motivo no vacío de hasta 250 caracteres.

La asignación inicial se puede enviar así:

```json
{
  "codusuNuevo": "8",
  "codusuEsperado": null,
  "motivo": ""
}
```

Una transferencia debe incluir el responsable observado y el motivo:

```json
{
  "codusuNuevo": "9",
  "codusuEsperado": "8",
  "motivo": "Reorganización de cartera"
}
```

El RPC vuelve a verificar permisos y que el destinatario tenga usuario y rol activos. Bloquea el lead antes de comparar el responsable esperado. Repetir el mismo destinatario responde correctamente sin duplicar el historial. Un responsable esperado obsoleto produce conflicto 409. No hay restricción por estado del lead.

## Base de datos y privacidad

`hu015_asignar_responsable_lead` actualiza solo `lead.codusu` e inserta el evento en la misma transacción. `hu015_listar_leads` calcula el alcance vendedor en la base de datos y devuelve una proyección comercial sin UUID, documentos ni datos de autenticación. `hu015_listar_responsables` devuelve solo los datos mínimos de presentación. Las tres funciones son `SECURITY DEFINER` con `search_path = ''`; solo `authenticated` puede ejecutarlas. La tabla de historial no concede CRUD directo y tiene RLS con política restrictiva denegatoria. No existe endpoint para consultar el historial.

La operación no cambia estado, observaciones, canal WhatsApp, seguimientos ni demás columnas del lead. No envía notificaciones ni hace asignación automática.
