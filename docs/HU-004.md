# HU-004 / EMT-68: configuración de techo

## Alcance

HU-004 registra la configuración de techo elegida para una unidad. No certifica que el techo se haya fabricado o instalado, ni que la unidad haya regresado del proveedor. El avance físico y la preparación pertenecen a HU-033. Esta implementación no crea estados de instalación ni una tabla de historial; no modifica `unidad.codepr`, `unidad.codubi`, `unidad.estcomuni` ni movimientos de ubicación.

Los tipos provisionados idempotentemente son:

| Tipo | `reqprotte` | Proveedor | Detalle |
|---|---:|---|---|
| Sin techo | false | ninguno | ninguno |
| Lona | false | ninguno | ninguno |
| Techo clásico de fibra | false | ninguno; fabricación EPSA Motor | ninguno |
| Techo de fibra deportiva | true | FIVESA, JAVICAR o FIBRAT, activo | opcional, hasta 250 caracteres |

El catálogo conserva tipos/proveedores preexistentes. Al reejecutar el seed solo corrige `reqprotte` de los cuatro tipos requeridos y no altera descripciones ni estados activos/inactivos. Los proveedores existentes no se duplican ni se modifican.

## Migración

Aplicar `supabase/migrations/202610080001_hu004_configuracion_techo.sql` después de las migraciones actuales hasta HU-012. No modifica migraciones aplicadas ni agrega columnas. Las RPC usan `SECURITY DEFINER` con `search_path` vacío, comprueban el rol mediante `hu026_rol_actual`, revocan EXECUTE de PUBLIC/anon y conceden a authenticated. No usan `service_role`.

La tabla `unidad` conserva las restricciones de HU-002: el acceso directo está bloqueado y las escrituras se realizan por RPC. No se debilitan RLS ni permisos existentes. La migración solo cambia `codtte`, `codpro` y `dettecuni` al actualizar una unidad.

## Endpoints

Todos requieren `Authorization: Bearer <access_token>` de Supabase Auth.

| Método | Ruta | Acceso |
|---|---|---|
| GET | `/api/unidades/catalogos/tipos-techo` | Gerente, Administradora, Vendedor |
| GET | `/api/unidades/catalogos/proveedores-techo` | Gerente, Administradora, Vendedor |
| GET | `/api/unidades/:id/techo` | Gerente, Administradora, Vendedor |
| PUT | `/api/unidades/:id/techo` | Gerente, Administradora |

`coduni`, `codtte` y `codpro` son cadenas BIGINT en JSON. Ejemplo de fibra deportiva:

```json
{
  "codtte": "4",
  "codpro": "2",
  "detalle": "Cámara de retroceso"
}
```

`codpro` y `detalle` se pueden omitir o enviar como null cuando no aplican. Para tipos que requieren proveedor, el proveedor es obligatorio y debe ser uno de los tres permitidos y estar activo. En los otros tipos se rechazan proveedor o detalle. Las cadenas se recortan, espacios consecutivos se normalizan y el detalle vacío se interpreta como null. Se rechazan campos ajenos, incluidos campos de preparación, ubicación, compra, modelo y series.

La consulta devuelve solo `coduni`, `tipoTecho` (`codtte`, `nombre`), `proveedor` (`codpro`, `nombre`) y `detalle`. Si la configuración actual aún no tiene tipo, `tipoTecho` es null. Las listas de selector solo contienen tipos activos y los tres proveedores externos permitidos que estén activos.

## Operaciones PostgreSQL

- `hu004_listar_tipos_techo()` devuelve catálogo activo.
- `hu004_listar_proveedores_techo()` devuelve proveedores externos activos permitidos.
- `hu004_obtener_configuracion_techo(p_coduni)` devuelve proyección mínima para los tres roles.
- `hu004_actualizar_configuracion_techo(p_coduni, p_codtte, p_codpro, p_detalle)` valida y actualiza atómicamente la configuración, solo para gerente y administradora.

Errores de regla tienen códigos controlados (`PT400`, `PT404`, `PT420`, `PT421`, `PT422`); la API responde 400, 404, 409 o 403 sin filtrar mensajes SQL. El ID inválido se rechaza con 400 antes de llamar la RPC.

## Verificación

`npm test` cubre middleware, contratos HTTP, roles, seed idempotente, combinaciones de proveedor, restricciones dentro de PostgreSQL y preservación exacta de ubicación, preparación, estado comercial, compra, modelo y series. `npm run build` compila TypeScript. `docs/HU-004.postman_collection.json` contiene solicitudes para seleccionar catálogos, consultar y cambiar configuración. No incluye instalación física, comunicación con proveedores, precios ni historial de preparación.
